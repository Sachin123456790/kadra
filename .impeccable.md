# Impeccable Design Context — Angainor (Angainor)

## Design Context

### Users
- **Primary**: Fund administrators (GPs, operations teams) managing private real estate fund back-office workflows — cap tables, settlements, distributions, transfers, audit exports
- **Secondary**: Limited Partners (investors) viewing portfolio positions, capital accounts, documents, and transfer history
- **Context**: Users are financial professionals accustomed to institutional-grade software. They work under regulatory pressure and need absolute confidence in data accuracy. Speed, clarity, and trust are paramount — every number, status, and timestamp must feel authoritative.
- **Job to be done**: Replace fragmented spreadsheets and manual processes with a single, verifiable system of record for fund administration

### Brand Personality
- **Three words**: Authoritative, Precise, Trustworthy
- **Voice**: Institutional and measured — like a top-tier bank or legal firm. Never casual, never flashy. Confident without being boastful.
- **Emotional goals**: Users should feel *in control*, *confident in the data*, and *reassured by the rigor* of the system. The UI should convey that this software handles serious financial operations with the gravity they deserve.

### Aesthetic Direction
- **Visual tone**: Clean institutional banking — structured, data-dense where needed, but never cluttered. Generous white space on summary views, tighter density on tables and ledgers.
- **References**: Carta/Pulley (cap table workflows), Stripe Dashboard (polish and clarity), JP Morgan/Goldman portals (institutional gravity), Anrok/Mercury (modern fintech cleanliness)
- **Anti-references**: Crypto/Web3 dashboards — absolutely no neon colors, dark-by-default themes, token price tickers, DeFi aesthetics, or blockchain-forward visual language. The blockchain is infrastructure, not identity.
- **Theme**: Light + dark mode (class-based toggle). Light is the default/primary experience.
- **Typography**: Inter (400/500/600/700). Clean, neutral, highly legible at small sizes for data tables.
- **Color palette**: Near-black primary (`hsl(0 0% 9%)` light, `hsl(0 0% 90%)` dark). Semantic colors for status: green (success/settled), red (destructive/rejected), amber (warning/pending), blue (info). Status pills use soft tinted backgrounds with darker text.
- **Icons**: Lucide React — consistent stroke weight, 20px/16px sizing
- **Illustrations**: unDraw SVGs only, accent color `#171717` (black). Always on white/transparent backgrounds — never wrapped in colored panels.
- **Border radius**: `0.5rem` base (`--radius`), creating slightly rounded but not bubbly shapes
- **Spacing**: Tailwind default scale. Cards use `p-4` (compact) to `p-6` (standard). Section headers use `px-6 py-4`.

### Design Principles

1. **Data integrity is visual** — Every number, hash, and timestamp should feel authoritative. Use monospace for hashes and transaction IDs. Align numbers right in tables. Never truncate financial figures.

2. **Hierarchy through restraint** — Use size, weight, and spacing to create hierarchy — not color or decoration. Reserve color for semantic meaning (status, alerts, actions). The quieter the default state, the louder the important signals.

3. **Density matches context** — Summary dashboards breathe with white space. Tables and ledgers earn their density. Never force one rhythm on both.

4. **Blockchain is plumbing, not branding** — On-chain references (hashes, contract addresses, block explorers) appear as secondary technical details, never as primary UI elements. The product is fund administration, not crypto.

5. **Institutional trust through consistency** — Every page should feel like it belongs to the same system. Consistent card styles, table patterns, status badges, and page headers. No one-off layouts or experimental components.

### Component Patterns (Existing)
- `SectionCard` — bordered card with optional title bar + action slot
- `MetricCard` — compact KPI display (label + large value + optional subtitle)
- `PageHeader` — page title + optional description + action buttons
- `StatusBadge` — semantic status pills (Pending/Settled/Rejected/etc.)
- `DataTable` — standard table wrapper for ledger views
- `ActivityFeed` — timestamped event stream (shared by admin + investor)
- `ExplorerLink` — Etherscan link for on-chain references (secondary, muted styling)
- `HashDisplay` — truncated hash with copy-to-clipboard

### Accessibility
- **Target**: WCAG 2.1 AA compliance
- **Contrast**: Minimum 4.5:1 for normal text, 3:1 for large text
- **Keyboard**: Full keyboard navigation for all interactive elements
- **Screen readers**: Semantic HTML, proper ARIA labels on icon-only buttons
- **Motion**: Respect `prefers-reduced-motion` for animations
- **Color**: Never use color as the only indicator — always pair with text/icon

### Text Color Convention
- On white/light backgrounds: use explicit Tailwind grays (`text-gray-900`, `text-gray-600`, `text-gray-500`) instead of CSS variable classes (`text-foreground`, `text-muted-foreground`) for guaranteed readability
- Dark mode overrides in `index.css` remap these hardcoded grays automatically

## Marketing / Public Landing Context (Angainor)

The **public marketing surface** runs under a separate brand, **Angainor**, with its own aesthetic distinct from the authenticated product (Angainor). This is per stakeholder spec (`feedback/Landing Page_ Angainor (2).pdf`) — not a drift.

### Why two surfaces
- **Product (Angainor, authenticated)**: institutional light mode, Carta/Stripe/JP Morgan references. Users are already sold; they need clarity and speed on dense operational data.
- **Marketing (Angainor, public)**: dark editorial, Harvey.ai / Carta marketing / Payna / Fairmint / Fume references. Users are a cold audience — the surface needs gravity, restraint, and story.

### Brand name
- Public-facing: **Angainor**. Used in nav, hero, CTA, footer, `mailto:` addresses (`founders@angainor.io`).
- Internal codebase / product: **Angainor**. No Angainor branding inside the authenticated app.

### Aesthetic (marketing only)
- **Theme**: Dark-by-default. Black (`#000`) background, white text at varying opacities (`white/90` body, `white/65` support, `white/45` eyebrows/meta).
- **Typography**:
  - Display: **Fraunces** (serif), light weight, tight tracking (`-0.02em`). Italics used sparingly as an emphasis mechanism.
  - Body: **Inter** (400/500/600). Small tracked uppercase for eyebrows (`tracking-[0.22em]`).
  - Mono: **JetBrains Mono** for hashes, refs, timestamps — ledger-adjacent content only.
- **Accent**: white only. No colored accents, no gradients for impact. One off-white panel (`#f4f4f1`) used once in "What Angainor Does" as a deliberate hierarchy break.
- **Surfaces**: `bg-white/[0.02]`–`bg-white/[0.05]` frosted cards on black. `border-white/10` hairline borders. `rounded-xl` / `rounded-2xl`.
- **Decorative motifs** (use sparingly): faint grid background with radial mask, dashed SVG connectors with animated dash-offset, soft floating animation on diagram cards.
- **References**:
  - [harvey.ai](https://www.harvey.ai/) — serif display + dark editorial + cycling focus card
  - [carta.com](https://carta.com) — institutional gravity
  - [payna.com](https://payna.com)
  - [fairmint.com](https://www.fairmint.com/)
  - [fume.finance](https://www.fume.finance)
- **Anti-references (still hold)**: neon, purple/blue gradients, glassmorphism used decoratively, hero-metric layouts, identical card-grid monotony, "Built on X" pill as hero real estate.

### Required sections (per spec)
1. **Nav bar** — logo + "Book a Demo", sticky, transparent-to-blurred on scroll
2. **Hero** — headline (serif) + subheading + single CTA (Request a Demo) + one-line DLT description
3. **Problem section** — animated mockup (6 source records floating, curved lines to central "Temporary truth" card) + eyebrow + headline + body + 3 problem cards
4. **What Angainor Does** — split panel (light left / dark right) with "Executed legal intent becomes structured fund data" + 6-tag grid
5. **Workflow Coverage** — 8 workflows cycled Harvey-style (one in focus, others fading), horizontal orientation preferred
6. **Audit Compliance** — 3-step horizontal path (Export Field → Ledger Record → Source Document) with hover interactions + "Included outputs" list
7. **Privacy and Control** — headline + 3 principle cards on left + stacked mockup panels on right (controlled storage, anchored record, role views, blurred "other participants")
8. **Closing + Footer** — "Angainor. The infrastructure revolutionizing fund operations." + footer links

### Voice (marketing)
- Declarative, institutional, no hype verbs. "Angainor eliminates…" not "Angainor revolutionizes…"
- Use italic-serif clauses for conceptual emphasis (e.g., "*one deterministic system of record*"). Once per headline maximum; do not stack.
- Technical terms (hash, timestamp, anchored) are fine — audience is sophisticated.

### Non-goals (marketing)
- No product screenshots above the fold. Mockups are diagrammatic, not literal UI.
- No pricing, no logos-of-customers strip, no "as seen in" press bar.
- No blog, no changelog, no comparison pages (yet).
